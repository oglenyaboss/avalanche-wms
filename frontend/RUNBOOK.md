# Ранбук: фронтенд WMS

Как запустить и пройти все складские операции руками (без физического сканера).

## Как это работает (важно понять один раз)

Приложение **сканер-ориентированное**. В реальной работе оператор наводит ТСД/сканер на
штрих-код или QR-наклейку (на грузоместе, коробке, товаре, ячейке, путёвке) — и поле
заполняется само. Без сканера ты **вводишь те же значения с клавиатуры** (у каждого поля
есть подпись «введите код вручную»). После ввода нажми кнопку рядом (или Enter).

Значения бывают двух видов:
- **Читаемые коды** — `ТТН-2026-GATE-001`, `CP-GATE-001`, `DSP-2026-0421-001`. Вводишь с головы.
- **UUID ячеек/грузомест** — длинные, типа `04162519-346a-40eb-929a-33e1743ecea1`. В бою они на QR-наклейке ячейки; без сканера их надо **подсмотреть запросом** (раздел 3). При каждом сбросе данных UUID меняются.

## 1. Запуск

Из корня репозитория:

```bash
# 1) бэкенд + блокчейн (профиль test поднимает локальный Avalanche + деплой контракта)
docker compose --profile test up -d --build
#    дождаться, пока avalanchego/kafka/postgres станут healthy (~1–2 мин):
docker compose ps

# 2) CDC-коннектор (Debezium → Kafka) регистрируется сам — контейнером connector-init при up.
#    Достаточно проверить (через ~30s после подъёма):
make connector-status      # должно быть "state":"RUNNING"
#    Фолбэк, если по какой-то причине не зарегался сам:
make register-connector

# 3) фронтенд
cd frontend && npm run dev # откроется на http://localhost:5173
```

> Без блокчейна можно проще: `docker compose up -d` (этапы будут работать, но в аналитике
> ончейн-статус останется PENDING). Для проверки именно аудита — нужен профиль `test` + коннектор.

Открыть: **http://localhost:5173**

## 3. Получить свои UUID-ячеек

UUID меняются при каждом сбросе данных. Выписать актуальные:

```bash
docker exec postgres_db psql -U root -d wms_blockchain_db -c \
"SELECT cargoplace_code, cargoplace_id FROM wms_inventory.cargoplaces WHERE cargoplace_code='CP-TABLE-001';
 SELECT code, bin_id FROM wms_inventory.bins WHERE code IN ('BUFFER-01','A-01-01','BIN-SHIP-5');
 SELECT dispatch_code FROM wms_inventory.outbound_dispatches;"
```

Запрос выведет **твои** значения для текущей сессии — держи их под рукой, они идут в поля
🔵 **UUID** на этапах ниже:

| Что | Куда вводится |
|---|---|
| `cargoplace_id` для CP-TABLE-001 | приёмка на столах, шаг 1 |
| `bin_id` для BUFFER-01 (буфер приёмки) | приёмка столы шаг 6, раскладка шаг 1 |
| `bin_id` для A-01-01 (ячейка хранения) | раскладка, шаг 4 |
| `bin_id` для BIN-SHIP-5 (буфер отгрузки) | сборка шаг 6, отгрузка шаг 1 |
| `dispatch_code` (`DSP-2026-0421-001`) | отгрузка, шаг 2 — это читаемый код, стабилен |

> UUID-ы меняются после каждого сброса данных, читаемые коды (ТТН, CP-GATE, рейс) — стабильны.

## 4. Прогон по этапам

Меню сверху: Приёмка на воротах → Приёмка на столах → Раскладка → Сборка → Отгрузка → Аналитика.
Логичный порядок прохождения: **столы → раскладка → сборка → отгрузка** (приёмка на воротах — отдельный независимый сценарий).

### 4.1. Приёмка на воротах (`/receiving/gate`)

Регистрирует прибытие грузомест. Блокчейн-события **не** создаёт (товаров ещё нет).

1. «Штрих-код ТТН» → `ТТН-2026-GATE-001` → **Подтвердить**.
2. Покажет 2 ожидаемых грузоместа, «Принято 0 из 2». Поле «Штрих-код грузоместа»:
   - `CP-GATE-001` → **Подтвердить** → «Принято 1 из 2»
   - `CP-GATE-002` → **Подтвердить** → поставка примется автоматически.

### 4.2. Приёмка на столах (`/receiving/table`)

Распаковка грузоместа в отдельные товары. **Создаёт receiving-событие в блокчейне** —
оно вылетает в самом конце, на шаге «Завершить грузоместо». Пока грузоместо не завершено,
событий нет, это нормально.

> **В каждом поле — свой тип значения, помечен иконкой:**
> 🔵 **UUID** — длинная строка из таблицы раздела 3, копируй целиком.
> 🟢 **новый код** — короткий, придумываешь сам (`BOX-1`, `QR-1`). Не UUID и не штрих-код.
> ⚪ **с экрана** — штрих-код из манифеста, приложение само его показывает.

1. 🔵 «Идентификатор грузоместа» → UUID **CP-TABLE-001** (раздел 3) → **Продолжить**.
   Покажет «Принято 0 из 4» и манифест ожидаемого.
2. 🟢 «Штрих-код коробки» → `BOX-1` → **Перейти к коробке**.
3. Каждый из 4 товаров = **два разных поля подряд**: сначала штрих-код (с экрана), потом QR
   (придумай новый). ⚠️ **В поле QR НЕ вводи штрих-код** — это отдельная «наклейка», новый код.

   | Товар | ⚪ Штрих-код товара (с экрана) | 🟢 QR-код (придумай новый) |
   |---|---|---|
   | 1 | `4600000099999` | `QR-1` |
   | 2 | `4600000000028` | `QR-2` |
   | 3 | `4600000000011` | `QR-3` |
   | 4 | `4600000000035` | `QR-4` |

   После четвёртого — «Принято 4 из 4».
4. **Принять коробку** → **Да**.
5. **Принять грузоместо** → **Да**.
6. 🔵 «Идентификатор ячейки буфера» → UUID **BUFFER-01** (раздел 3) → **Принять товар**.
   ⚠️ **Не пропусти этот шаг** — без UUID буфера грузоместо не завершится (тут ты застрял прошлый раз).
7. **Завершить грузоместо** → **Понятно**. ← здесь создаётся receiving-событие в блокчейне.

### 4.3. Раскладка (`/putaway`)

Перенос товаров из буфера в ячейку хранения. **Создаёт putaway-события.**

1. 🔵 «Идентификатор буфера приёмки» → UUID **BUFFER-01** (раздел 3) → **Подтвердить**.
2. 🟢 «QR-код товара» → `QR-1`, `QR-2`, `QR-3`, `QR-4` — те же коды, что придумал в приёмке
   (каждый → **Добавить**).
3. **Перейти к раскладке**.
4. 🔵 «Идентификатор ячейки хранения» → UUID **A-01-01** (раздел 3) → **Далее**.
5. 🟢 «QR-код товара» → `QR-1` … `QR-4` (каждый → **Положить**).
6. **Завершить задачу** → **Да**.

### 4.4. Сборка (`/assembly`)

Сбор заказа из складского стока. **Создаёт picking-события.**

1. Выбрать **«Магазин №5 Маросейка»**.
2. **Аллоцировать заказы** (создаст задачи сборки из товаров на хранении). Появится «Задач: 10».
3. **Начать сборку**.
4. 🟢 «Данные с QR-кода» → вводи по очереди **10 QR сид-товаров** (в бою оператор берёт их с
   листа подбора), каждый → **Добавить**, счётчик «Взято» растёт до 10:

   `QR-2026-0009` `QR-2026-0010` `QR-2026-0011` `QR-2026-0012` `QR-2026-0013`
   `QR-2026-0014` `QR-2026-0015` `QR-2026-0016` `QR-2026-0017` `QR-2026-0018`

   > Кнопка «Товары к сборке (N)» показывает уже **собранное** (корзину), а не список к подбору —
   > поэтому в начале там 0, это не баг. Если после сброса QR не совпали — выписать запросом:
   > `SELECT p.qr_code FROM wms_ops.assembly_tasks t JOIN wms_inventory.products p ON p.product_id=t.product_id ORDER BY 1;`
5. **Перейти к буферу отгрузки** (кнопка активна после «Взято: 10»).
6. 🔵 «Идентификатор буфера отгрузки» → UUID **BIN-SHIP-5** (раздел 3) → **Разместить**.

### 4.5. Отгрузка (`/shipping`)

Погрузка собранного в машину. **Создаёт shipping-события.**

1. 🔵 «Идентификатор буфера отгрузки» → UUID **BIN-SHIP-5** (раздел 3) → **Осмотреть буфер**.
   Покажет «N товаров готово к отгрузке».
2. «Код рейса» → `DSP-2026-0421-001` → **Зарегистрировать**.
   Покажет водителя и проверку «Зоны совпадают».
3. **Отгрузить весь буфер (N)** → «Отгрузка завершена», в т.ч. «Событий блокчейна создано: N».

### 4.6. Аналитика (`/analytics`)

Открыть страницу: «ВСЕГО СОБЫТИЙ» и «ПОДТВЕРЖДЕНО» должны вырасти после твоих операций,
подтверждение стремится к 100%, по этапам — Приёмка/Раскладка/Сборка/Отгрузка, в «Последних
транзакциях» — реальные tx-хэши Avalanche.

Сверка с блокчейном напрямую:
```bash
docker exec postgres_db psql -U root -d wms_blockchain_db -c \
"SELECT aggregate_type, status, count(*) FROM public.onchain_events GROUP BY 1,2 ORDER BY 1,2;"
```
COMMITTED появляется не мгновенно: батч → SENT, затем reconcile (до ~30 сек) → COMMITTED.

## 5. Сброс данных (для нового чистого прогона)

Возвращает инвентарь к свежему seed; ончейн-события и пользователей **сохраняет**:

```bash
docker exec postgres_db psql -U root -d wms_blockchain_db -c \
"TRUNCATE wms_inventory.warehouses,wms_inventory.skus,wms_inventory.sku_barcodes,wms_inventory.destinations,wms_inventory.bins,wms_inventory.inbound_shipments,wms_inventory.cargoplaces,wms_inventory.boxes,wms_inventory.expected_cargoplace_skus,wms_inventory.products,wms_inventory.orders,wms_inventory.order_lines,wms_inventory.outbound_dispatches RESTART IDENTITY CASCADE;"
docker exec postgres_db psql -U root -d wms_blockchain_db -f /deploy/seed.sql
```

После сброса **заново выпиши UUID** (раздел 3) — они изменятся.

## 6. Остановить всё

```bash
# фронт — Ctrl+C в терминале с `npm run dev`
docker compose --profile test down        # остановить сервисы (данные сохранятся)
docker compose --profile test down -v      # + стереть данные и блокчейн полностью
```

### Частые вопросы

- **Поле не принимает значение / кнопка серая** — проверь, что ввёл точно (UUID без пробелов;
  штрих-код полностью). Для UUID-полей читаемый код (`BUFFER-01`) не подойдёт — нужен именно UUID.
- **«Сессия истекла»** — access-токен живёт 15 мин, но после фикса сессия сама обновляется;
  если всё же выкинуло — просто залогинься снова (`operator`/`operator`).
- **В аналитике 0 / не растёт** — не поднят блокчейн-профиль или не зарегистрирован коннектор
  (раздел 1, шаги 1–2), либо события ещё в статусе SENT (подожди ~30 сек).
