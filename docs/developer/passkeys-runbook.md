# Ранбук: passkey и реестр ключей организации

Как руками пройти всю цепочку: создать passkey в браузере → выгрузить ключ админа → зарегистрировать организацию в цепи → проверить ончейн-статус → отозвать и заменить ключ.

## 1. Что проверяем

Регистрацию passkey для подписи действий и on-chain реестр ключей. Вход в приложение по-прежнему по паролю. Пользователь создаёт passkey на странице «Мой ключ», админ выгружает файл с ключом организации, владелец контракта регистрирует организацию и ключ админа через CLI адаптера, после чего статус ключа подтверждается в цепи. Ключ оператора админ подтверждает подписанным действием, после чего он регистрируется в цепи (модель — [key-management](../integration/key-management.md)).

## 2. Запуск

Из корня репозитория:

```bash
# KMS-стек:
make kms-up
# или без KMS:
docker compose --profile test up -d --build
```

Если порт 9090 на хосте занят — задай другой перед командой (или в `.env`): `PROMETHEUS_PORT=9091`.

Первый старт после этих изменений требует свежей цепи (команда сносит БД и цепь):

```bash
docker compose -f docker-compose.yaml -f docker-compose.kms.yaml --profile test down -v
```

На свежей цепи `docker logs contract_deploy` должен показать:

```
==> Deployed ConsortiumRegistry at 0x52C84043CD9c865236f11d9Fc9F56aa003c1f922
```

Фронтенд:

```bash
cd frontend && npm ci && npm run dev   # откроется на http://localhost:5173
```

Если 5173 занят: `npx vite --port 5174`, добавь `http://localhost:5174` в `WEBAUTHN_RP_ORIGINS` в `.env` (список через запятую, по умолчанию `http://localhost:5173`), затем `docker compose up -d --no-deps wms_app`.

## 3. Что нужно браузеру

- Браузер плюс аутентификатор с PIN или биометрией: менеджер паролей с поддержкой passkey, телефон по QR-коду или USB-ключ. Сервер требует user verification и алгоритм ES256.
- Приватный ключ остаётся на устройстве; сервер хранит только публичный ключ (qx, qy) и keyId = keccak256(qx‖qy).
- Открывать приложение только через `http://localhost:<порт>`, не через `127.0.0.1`: WebAuthn RP ID — `localhost` (`WEBAUTHN_RP_ID`).

## 4. Сценарий: ключ админа и регистрация организации

Пользователи из сида:

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | из `ADMIN_PASSWORD` в `.env` (по умолчанию `admin`) | ADMIN |
| `operator` | `operator` | OPERATOR |

Оба состоят в организации «Демо-склад», orgId `01929c5e-0000-7000-8000-00000000a001`.

1. Залогинься как `admin`.
2. Меню **«Мой ключ»** → `/passkey`. Нажми **«Создать ключ»**, браузер спросит аутентификатор (PIN/биометрия).
3. Статусы на странице: «Ожидает подтверждения» (PENDING), «Активен в цепи» (ACTIVE), «Отклонён» (REJECTED), «Отозван» (REVOKED). После создания — PENDING.
4. Меню **«Ключи организации»** → `/organization/keys`. Таблица: Пользователь, Роль, Статус ключа, Key ID. Нажми **«Скачать ключ админа»** — скачается `org-<orgId>.json`. Без своего ключа админа кнопка отвечает: «Сначала создайте свой ключ на странице «Мой ключ»».
5. Скопируй файл в корень репозитория:

```bash
cp ~/Downloads/org-01929c5e-0000-7000-8000-00000000a001.json ./org.json
```

   Формат файла: `{"orgId":"<uuid>","name":"…","qx":"0x…","qy":"0x…"}` — именно его и выгружает кнопка.

6. Зарегистрируй организацию (ключ админа берётся из файла):

```bash
make registry-cli ARGS="register-org --file org.json"
# организация 01929c5e-0000-7000-8000-00000000a001 «Демо-склад» зарегистрирована, ключ админа 0x…, tx 0x…
```

   Если организация или ключ уже существуют — CLI откажет.

7. Перегрузи «Мой ключ»: статус станет «Активен в цепи» (ACTIVE). Статус перечитывается из цепи при каждой загрузке страницы: PENDING → ACTIVE, когда ключ появился в реестре, → REVOKED после отзыва.

8. Проверь реестр:

```bash
make registry-cli ARGS="list"
```

   CLI печатает организации и ключи из событий цепи; у каждого ключа роль `admin|operator` и статус `активен|отозван`. Пустая цепь печатает `организаций нет`.

## 5. Сценарий: оператор

1. Залогинься как `operator` / `operator`.
2. «Мой ключ» → «Создать ключ» → статус PENDING.
3. Ключ оператора остаётся «Ожидает подтверждения», пока админ не подтвердит его подписанным действием: «Ключи организации» → «Подтвердить ключ». После записи в цепь статус станет ACTIVE.
4. Пункта меню «Ключи организации» у оператора нет; прямая ссылка `/organization/keys` покажет ошибку доступа.
5. Админ в «Ключи организации» видит строку оператора (Пользователь, Роль, Статус ключа, Key ID).

## 6. Сценарий: отзыв и замена ключа админа

Аварийный отзыв делает владелец контракта (owner) через `cast` из foundry-образа. Префикс volume `avalanche-wms_` — это имя compose-проекта.

```bash
RPC=$(docker run --rm -v avalanche-wms_shared_state:/shared:ro alpine cat /shared/rpc_url.txt | sed 's#subnet-node1#127.0.0.1#')
REG=$(docker run --rm -v avalanche-wms_shared_state:/shared:ro alpine cat /shared/registry_addr.txt)
OWNER=$(docker run --rm -v avalanche-wms_shared_state:/shared:ro alpine cat /shared/deployer_key.txt)
docker run --rm --network host --entrypoint cast ghcr.io/foundry-rs/foundry:stable \
  send "$REG" 'revokeKey(bytes32)' <keyId> --private-key "$OWNER" --rpc-url "$RPC"
```

Полный keyId: наведи курсор на Key ID на «Мой ключ», или из API `GET /api/passkeys/me` (поле `key_id`).

1. Перегрузи «Мой ключ» — статус «Отозван» (REVOKED).
2. Кнопка «Создать ключ» снова доступна: она показана, когда ключа нет или он REJECTED/REVOKED. Создай новый ключ (PENDING).
3. Скачай файл заново («Скачать ключ админа») и добавь новый ключ к уже зарегистрированной организации:

```bash
make registry-cli ARGS="add-admin-key --file org.json"
# ключ админа 0x… добавлен в организацию 01929c5e-0000-7000-8000-00000000a001, tx 0x…
```

   Именно `add-admin-key`, не `register-org`: организация уже существует, `register-org` откажет.

4. Перегрузи «Мой ключ» — «Активен в цепи» (ACTIVE).

## 7. Как посмотреть статус напрямую

Адаптер:

```bash
curl -s localhost:8085/registry/keys/<keyId>
# {"found":false}
# {"found":true,"org_id":"…","role":"admin","active":true}
```

- Некорректный keyId → 400 `{"error":"INVALID_KEY_ID"}`.
- У адаптера нет `REGISTRY_ADDR` → 502 `{"error":"CHAIN_UNREACHABLE"}`.

Реестр целиком: `make registry-cli ARGS="list"` (пустая цепь печатает `организаций нет`).

## 8. Сброс

```bash
docker compose -f docker-compose.yaml -f docker-compose.kms.yaml --profile test down -v
```

Сносит БД и цепь: организации и ключи нужно регистрировать заново.

## 9. Если что-то не так

| Симптом | Причина / решение |
|---|---|
| «Браузер запретил создание ключа на этом адресе» | Приложение открыто не через `localhost`, например через `127.0.0.1`: RP ID — `localhost` |
| «Некорректная регистрация passkey» | Origin не в `WEBAUTHN_RP_ORIGINS`, либо аутентификатор не подтвердил пользователя (нет PIN/биометрии) |
| «Создание ключа отменено или истекло время ожидания» | Закрыл диалог браузера или истёк таймаут — нажми ещё раз |
| Статус остаётся PENDING после `register-org` | У адаптера нет адреса реестра: `docker logs ledger-adapter \| grep registry_addr`, `curl` возвращает 502 |
| `организация … уже зарегистрирована` | Используй `add-admin-key` или сбрось цепь |
| «Пользователь не принадлежит организации» | Сид привязывает к «Демо-склад» только `admin` и `operator` |
